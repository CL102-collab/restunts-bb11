# MT-32 audio and ROM setup

Desktop, Android and browser SDL3 builds can emulate Roland MT-32-family music
and effects through Munt libmt32emu. AdLib remains the default. Original DOS16
builds keep their executable drivers; DOS32 supports hardware Ad Lib/OPL and
PC Speaker. Amiga and TempleOS retain their existing audio backends.

Choose **MT-32** in **Sound settings**, select your own ROM folder, and select a
model if needed. The sound mode is separate from **OGG music replacement**
(formerly **New MIDI**): replacements affect music, while engines and effects
use the chosen synthesizer. Turn replacements off to hear original MT-32 music.

## ROM folder and detected models

The emulator needs compatible Roland control and PCM ROM dumps. These are
proprietary data, separate from the emulator's LGPL license. No ROMs are bundled
or downloaded by Chocolate Stunts. Provide ROMs you are entitled to use.
`MT32.PLB` in the original game is a custom instrument bank, not a hardware ROM.
The original `MTENG1.VCE`, `MTSKIDMS.VCE`, `MT32.PLB` and music/effect resources
are still required in the selected Stunts game-data folder.

ROM files are identified by their contents, not by an assumed filename or
extension. Supported full dumps and recognized split dumps are combined into
complete compatible sets. Old and new original MT-32 models share the same PCM
sample image but use different control ROMs; CM-32L-family models use their
matching expanded PCM image. Arbitrary sample banks and SoundFonts do not replace
these ROMs.

The detected list comes from the pinned Munt library, including its recognized
original MT-32, BlueRidge and CM-32L-family models. When exactly one complete set
is present, it is selected automatically. When more than one complete model is
available, choose explicitly; files are never selected by directory order or
an arbitrary preference for the newest version. Unsupported, incomplete or
ambiguous selections produce an actionable error. MT-32 mode does not silently
fall back to AdLib.

Desktop launchers remember a normal folder path. Android remembers a read-only
system-picker URI and maintains a separate app-private ROM mirror; a URI is not
passed to the native backend as a filesystem path. Browser builds remember a
read-only directory handle where supported, with permission renewed by a click
when required. In browsers using the fallback directory input, select the ROM
folder each visit. ROMs remain separate from game saves and save exports.

## Command line

```sh
restunts --data-dir /path/to/stunts --soundmode:mt-32 \
    --mt-32-rom-dir /path/to/roms
```

`--data-dir` must remain first. Add an explicit detected model ID when the ROM
folder contains several complete sets, for example:

```sh
restunts --data-dir /path/to/stunts --soundmode:mt-32 \
    --mt-32-rom-dir /path/to/roms --mt-32-model mt32_1_07 --ogg:off
```

List the detected ROM inventory without loading game data or initializing SDL:

```sh
restunts --list-mt-32-roms /path/to/roms
```

This writes JSON, including errors and the complete compatible model choices.
Use `--soundmode:adlib` for original Ad Lib synthesis or
`--soundmode:pc-speaker` for original PC Speaker music and effects without ROMs.
PC Speaker uses normal PCM output on desktop/Android/web and the real speaker
on DOS32. `--nosound` and its legacy
alias `/ns` disable music and effects regardless of argument order or selected
sound mode. `--ogg:on/off` controls replacement music independently.

ROM selection is validated before audio playback begins. Audio device or
synthesizer initialization errors are reported explicitly. The selected game-data
folder remains writable for saves; the ROM folder only needs read access.
